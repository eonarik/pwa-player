# Changelog 0.18.x

> Релизы: 0.18.0

## [0.18.0] - 2026-11-11

### Added

- `Track.duplicateTrackIds: TrackId[]` — симметричные связи треков-дубликатов из библиотеки.
- `SimilarityLevel` и функция `similarityLevel(similarity)` для уровней точности в UI.
- Новый writer-API `updateTrackDuplicates(id, duplicateTrackIds)`.
- Модуль `apply/duplicates.ts`: `pickPrimaryTrackId`, `applyDuplicates`.
- `RemoteMetadataModal.vue` — отдельная модалка для внешних кандидатов (вид B).
- `MetadataCandidatesModal.vue` переделана в «Похожие треки»: BFS-группировка по `duplicateTrackIds`, кандидаты в DropdownMenu, кнопка «Сделать основным» вместо radio.
- `MetadataCandidatesButton.vue` показывает два счётчика (группы дубликатов / внешние метаданные) и две кнопки; бейдж отражает число групп, а не кандидатов.
- Unit-тесты `duplicates.spec.ts` (9 сценариев: pick + apply пары/треугольника/edge-cases).
- Unit-тесты `merge-same-title.spec.ts`: mergeMany склеивает 2 и 3 payload с одинаковым artist/title в разных folderId; разные треки не склеиваются.

### Changed

- `MergeAction`: `'merged-soft'` заменён на `'linked-duplicate'` — при soft-совпадении создаётся физический трек с симметричной ссылкой `duplicateTrackIds`, а не кандидат.
- `mergeMany` прописывает обратные ссылки у найденного дубля во всех списках индекса, чтобы следующий payload видел связь.
- `apply.ts` обрабатывает `linked-duplicate`: добавляет новый трек + обновляет `duplicateTrackIds` у существующего.
- `applyCandidate` больше не содержит ветку `mergeWithTrackId` — кандидаты только внешние.
- Тесты `TrackMerger.spec.ts`, `history.spec.ts` обновлены под новую семантику `linked-duplicate`.

### Fixed

- `normalizeMatchString` вместо `(artist || '').trim().toLowerCase()` в трёх местах:
  - `applySetLibrary` (`writer/index.ts`) — индекс строится с NFC/диакритикой
  - `mergeMany` (`merge.ts`) — обновление индекса после merge
  - `tracksByArtist` (`computed.ts`) — реактивный индекс для history/dislikes
    Это устранило ситуацию, когда одинаковые треки из разных папок (или плагинов)
    не находили друг друга из-за расхождения ключей (NFD vs NFC).
- Мержер не склеивал одинаковые треки из разных подпапок одной папки: при
  подключении папки дубликаты (одинаковые artist/title) попадали в
  «Проблемные совпадения» как soft-кандидаты (90%) вместо merged-strict.
  - `mergeMany` строил ключ `libraryIndex` по сырому artist, а искал по
    нормализованному (`normalizeMatchString`) — индекс теперь пополняется через
    ту же нормализацию.
  - При `merged-strict` запись в индексе оставалась старым снимком трека без
    добавленного source — следующий payload склеивался со снимком и терял
    источник. Теперь запись заменяется на актуальный трек.

### Removed

- Поле `extMetadata.mergeWithTrackId` из `MetadataCandidate` (упразднено).
- Сценарий D (`applyCandidate с mergeWithTrackId`) удалён из тестов.
- Неиспользуемые импорты `newMetadataCandidateId`, `toTrackId`, `useLibraryStore` из `candidate.ts`.

### Migration

- `SCHEMA_VERSION` поднят до **2**. При загрузке приложения сохранённая версия сравнивается — при несовпадении данные в IDB очищаются перед первым чтением (принято для 0.x).

### Docs

- Confluence-подобная документация проекта в `docs/`: архитектура, модель данных,
  плагины, сервер, stores, сервисы, соглашения.
- AST-скрипт `scripts/generate-docs-manifest.ts` и npm-скрипты `docs:manifest`,
  `tree-generate` (STRUCTURE.md переехал в `docs/STRUCTURE.md`).
