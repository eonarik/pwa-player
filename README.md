# CUEI Media Player

Офлайн PWA-плеер для музыкальной библиотеки. Работает напрямую с локальной файловой системой через File System Access API, а также с Яндекс.Диском через собственный прокси. Без загрузки файлов на сторонние серверы, без аккаунтов, без интернета для локальной библиотеки.

## Возможности

**Локальная библиотека:**

- Прямой доступ к папкам через системный диалог, рекурсивное сканирование подпапок.
- Чтение ID3-тегов и обложек из тегов или файлов `folder.jpg` / `cover.jpg`.
- Навигация по папкам с хлебными крошками.
- Персистентность: библиотека, очередь и позиция воспроизведения сохраняются в IndexedDB.

**Яндекс.Диск:**

- Подключение к папке на Диске через локальный прокси.
- Рекурсивное сканирование с распараллеливанием (5 запросов одновременно).
- Кэширование в IndexedDB с TTL 24 часа — повторное подключение мгновенно.
- Автоподключение при старте, если последний источник был Диск.
- Точечное рекурсивное обновление текущей папки и её поддерева (не трогает родительские и соседние ветки).
- **Скачивание на устройство** — одиночный трек, папка рекурсивно, плейлист. Состояния `[облако]` / `[скачан]` / `[только локально]`, круговой прогресс, отмена.
- **Общая папка-спейс** для всех облачных источников — `cuei-{pluginId}` внутри выбранной пользователем папки.
- **Синхронизация с устройством** — скан папки скачивания, находит новые и отсутствующие треки.

**Плеер:**

- Очередь, shuffle, repeat (off / all / one), громкость, seek.
- Media Session API — управление с локскрина и наушников.
- Горячие клавиши: Space, стрелки, N/P, M.
- Виртуализация списка через `requestAnimationFrame` и `ResizeObserver` с автоизмерением высоты.
- Клик по иконке папки — играть всю папку рекурсивно.
- Подсветка играющей папки, play/pause прямо на иконке.
- Панель текущей очереди воспроизведения — отдельный роут `/queue` с подсветкой играющего трека, удалением по одному и полной очисткой.
- Тосты-уведомления и тост обновления PWA с кнопкой «Перезагрузить».

**Поиск обложек:**

- Подтягивание обложек для треков без тегов или `folder.jpg`.
- iTunes Search API (приоритет) + Deezer (fallback).
- Кэш в IndexedDB: найденное — навсегда, `null` — TTL 7 дней.
- Кнопка «Найти обложки» с прогрессом и сбросом.

**Плейлисты и история:**

- Пользовательские плейлисты с добавлением из контекстного меню.
- Системный плейлист «Избранное» — toggle с сердечка.
- История воспроизведения с режимами «Уникальные» / «Все».
- Все данные хранятся в IndexedDB.

**Авторизация (Яндекс.Диск) (это временное решение, в будущем авторизация будет не через токен, а через OAuth):**

- Файл `.settings.json` в корне музыкальной папки.
- Пароль для доступа к приватным папкам, белый список публичных.
- JWT-сессии (30 дней) с хранением токена в `localStorage`.
- Фильтрация ответа на бэкенде: неавторизованный пользователь видит только публичные папки.

**PWA:**

- Манифест, Service Worker, офлайн-кэш.
- Safe-area для iPhone, отключены overscroll и двойной тап-зум.
- Адаптивная вёрстка: компактный плеер на мобильных, полный — на десктопе.

**Плагины:**

- Архитектура источников на плагинах. Ядро не знает про конкретные источники — только про контракт `LibrarySource`.
- Автоматическая регистрация через `import.meta.glob` — достаточно создать `src/plugins/{id}/manifest.ts`, плагин появится в реестре.
- Удаление плагина = удаление папки. Отключение = `enabled: false` в манифесте.
- Встроенные плагины: `local` (локальная папка), `yandex` (Яндекс.Диск).
- Изолированное хранилище на плагин (`PluginStorage` → IDB store `cuei-plugins/{pluginId}`).
- `LibraryWriter` — API ядра для наполнения библиотеки; плагин не лезет в Pinia.
- `PluginContext` — `showModal`, `showToast`, `fetchCover`, `getDownloadDir`, `storage`.

## Требования

### Десктоп

**Браузер:** Chrome 86+, Edge 86+, Opera 72+.

**Не поддерживается:**

- Firefox — нет File System Access API.
- Safari — нет File System Access API.

### Мобильные

**Локальная библиотека не работает** — File System Access API недоступен ни на iOS, ни на Android.

**Яндекс.Диск работает** через прокси. Есть нюансы:

- На iOS аудио в PWA (добавленной на домашний экран) может не играть из-за бага WebKit. Используйте обычный Safari или Chrome.
- Если провайдер или ТСПУ блокирует TLS 1.3 — на сервере отключён TLS 1.3, оставлен только TLS 1.2.

### Как получить OAuth-токен:

- Создай приложение на https://oauth.yandex.ru/ типа «Для доступа к API или отладки».
- Добавь разрешения cloud_api:disk.read и cloud_api:disk.info.
- Открой https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>.
- Скопируй токен из адресной строки и вставь в .env.

## Поиск обложек

Фронт умеет искать обложки для треков, у которых их нет в тегах или folder.jpg. Работает через прокси, который обращается к iTunes Search API и Deezer API.

#### Приоритет источников

- iTunes Search API — первым.
- Deezer API — fallback.

## Ключевые архитектурные решения

**Нормализованная библиотека.** Папки и треки хранятся плоскими `Record<string, Folder>` и `Record<string, LibraryTrack>`, а не деревом. Связи — через parentId и childFolderIds / trackIds. Это удобнее для виртуализации и сериализации.

**Разделение стора плеера и библиотеки.** player ничего не знает про библиотеку — он работает с очередью `Track[]`. Библиотека живёт отдельно и наполняет очередь через setQueue. Это позволяет позже добавить другие источники (плейлисты, Яндекс.Диск).

**Плагины как источники.** Ядро не знает, что внутри источника: локальная папка, Яндекс.Диск, будущий Dropbox. Всё общение — через контракт `LibrarySource` (`connect`, `load`, `restoreFromCache`, `refreshFolder`, `buildStreamUrl`, `downloadTrack`, `removeDownloaded`, `scanDownloadDir`, `disconnect`). Реестр находит плагины через `import.meta.glob('./*/manifest.ts')`. Плагин получает `PluginContext` и работает через него — не импортирует Pinia и `library.ts` напрямую.

**`LibraryWriter` для наполнения библиотеки.** Плагин не пишет в `folders.value` / `tracks.value` напрямую. Он зовёт `writer.setLibrary()`, `addTracks()`, `updateFolder()`, `updateTrackOrigin()`. `setLibrary` заменяет папки и треки **только указанного `sourceId`** — чужие плагины не трогаются. Это позволяет нескольким источникам сосуществовать в одном сторе.

**Мульти-источник.** URL определяет источник: `/folder/:pluginId/:path(.*)*`. Корень плагина — папка с `parentId: null` и `source: pluginId`. Плеер и плейлисты работают со смешанными треками — каждый трек знает свой `pluginId`.

**`origin` трека.** `LibraryTrack.origin: 'remote' | 'downloaded' | 'only-local'`:

- `remote` — есть в облаке, локальной копии нет.
- `downloaded` — есть в облаке и скачан на устройство.
- `only-local` — файл в папке скачивания, в облаке его нет.

**Скачивание — в плагине, оркестрация — в ядре.** Плагин знает, как получить URL и записать файл. Ядро (`DownloadOrchestrator`, `DownloadSpaceService`, `SyncService`) управляет папками, прогрессом, отменой, состояниями. Утилиты `downloadUrlToFile`, `scanDirectory`, `getFileFromPath` — общие в ядре, чтобы не дублировать код между плагинами.

**Общая папка-спейс.** Одна папка для всех облачных источников (`showDirectoryPicker` при первом скачивании). Внутри — подпапки по `pluginId`: `cuei-{pluginId}`. Локальный источник не участвует в спейсе.

**Ленивое получение длительности.** Для облачных треков `duration` неизвестна (нужен парсинг файла). Она подтягивается при первом воспроизведении через `loadedmetadata` и сохраняется в IDB плагина с дебаунсом (`LibrarySaveService`). До первого воспроизведения показывается `--:--`.

**Плейлисты хранят снимки, а не ссылки.** PlaylistTrackSnapshot содержит trackId, title, artist, remotePath. Это устойчиво к смене источника: даже если трек недоступен, плейлист помнит, что там было.

**URL как источник правды для навигации.** Текущая папка определяется URL (`/folder/путь/к/папке`). Стор `library.currentFolderId`— зеркало URL. Это даёт работающие `back/forward`, закладки и восстановление после перезапуска.

**Виртуализация без фиксированной высоты.** Высота элемента измеряется через ResizeObserver на скрытом эталоне. Меняешь дизайн `TrackListItem` — виртуализация подстраивается сама.

**Прокси для Яндекс.Диска.** CORS-политика Яндекса не даёт браузеру ходить к cloud-api.yandex.net напрямую. Тонкий Node-прокси добавляет OAuth-токен и CORS-заголовки. Токен хранится только на сервере.

**Кэш Диска с TTL.** Библиотека Диска хранится в IndexedDB под отдельным ключом, с TTL 24 часа. При повторном подключении — мгновенная загрузка из кэша. При старте — автоподключение, если последний источник был Диск.

**Кэш обложек по trackId, а не по artist|album.** URL обложек хранятся как строки (не blob), что не раздувает IDB. Deezer-обложка навсегда, null — с TTL 7 дней

**Очередь как источник правды в плеере.** `player.queue` — массив `Track[]`, `currentIndex` указывает на играющий. Удаление трека из очереди (`removeFromQueue`) корректно сдвигает индекс: если удалили играющий — переключается на следующий; если удалили до текущего — индекс уменьшается без перезапуска воспроизведения; если после — ничего не меняется. Очередь живёт независимо от библиотеки, что позволяет позже наполнять её из плейлистов, истории и других источников.

## Деплой

### VPS (production)

Проект задеплоен на VPS с Ubuntu 24.04.

**Стек сервера:**

- Node.js 22
- Nginx 1.24 (reverse proxy + раздача статики)
- PM2 (менеджер процессов для бэкенда)
- Certbot (Let's Encrypt SSL)

**PM2:**

```bash
cd /var/www/cuei-player/pwa-player/server
pm2 start src/index.mjs --name cuei-backend
pm2 save
pm2 startup
```

**Автодеплой через GitHub Actions:**

При пуше в `main` workflow собирает фронт на GitHub runner, заливает `dist/` на сервер по `scp`, обновляет бэкенд и перезапускает PM2.
